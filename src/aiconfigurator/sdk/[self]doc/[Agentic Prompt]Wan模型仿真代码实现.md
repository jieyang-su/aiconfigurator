1. 以sglang中的代码为参考基准（docker库中源码）：我们已完成了这部分的代码剖析和模型拆解。只考虑USPAttention的模型主路，对于SLA/VSA特性不作考虑。
2. 遵循aiconfigurator - sdk组件的实现习惯。
   - 如models直接为ops组成的列表序列、ops为算子表征到性能实际分析后端之间的中介层、perf_database对于每种算子实现sol/empirical模式（理论估算）和silicon（数据查表实测）等。
   - 对于库中已有的组件可以复用（典型如gemm等），未囊括的算子再考虑新建
   - 考虑sglang支持的并行算法，在仿真代码中也进行实现。
3. 考虑视频模型的新形态，整体做相应的适配（如inference_session、runtime_config等组件可能需要修改或新的实现）。
   - 现有代码基本是针对LLM语言模型，而视频模型在输入维度、处理组件等与LLM有一定不同，因此在前端也需要做相应的修改，新增对视频模型的适配能力。
   - 对已有的适用于LLM的前端尽量不做侵入式改动，可能考虑新增新类和方法，保持不同类型模型的独立性。
4. 对于部分未实测的单元（如通信单元），先检查现有框架是否有可复用的模块，抑或先忽略通信单元（考虑实现一种Mock类型的通信算子，在代码中暂时起到占位作用，起到保持模型和推理路径表征完整的目的。未来再作实现）。
5. 算子实测数据目录：systems/data/h100_sxm/sglang/0.5.1.post1-wan2.2-main0515。其中包含了先前完成的collect的wan所需算子实测结果，基本无错误应能较好地满足需求。
