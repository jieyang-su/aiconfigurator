# vLLM collector 算子实测档案

## Registry 覆盖

vLLM CUDA `REGISTRY` 覆盖 GEMM、Attention、MoE、MLA/DSA module、GDN。`REGISTRY_XPU` 单独覆盖 XPU GEMM、Attention、MoE；本报告在附表记录。版本分叉集中在 `collect_moe_v1/v2.py` 与 `collect_mla_module_v1/v2/v3.py`。

| 所属文件与注册标识 | 测试粒度界定 | 核心执行载体 | 包含的量化类型与前置转化全景 | 输入变量与保存的数据表 | 代码执行过程要点解析 | 特殊设计 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `collect_gemm.py`；`op=gemm`；`PerfFile.GEMM` → `gemm_perf.txt` | 底层 Linear/GEMM 单算子。 | vLLM `ReplicatedLinear` / quantized Linear、`vllm._custom_ops`、DeepGEMM。 | `bfloat16`、SM>86 `fp8`、SM90+ `fp8_block`、SM100+ `nvfp4`；权重量化和 quant config 在 op 构造期，主测为 `op.forward(x)`。 | `gemm_dtype,m,n,k,latency`。 | 设置 `VLLM_USE_DEEP_GEMM=1` → setup distributed → 构造多份 Linear → `kernel_func` 顺序 forward → benchmark → 写 `kernel_source=vllm_default`。 | `outside_loop_count` 多 op 摊薄误差；使用 `with_exit_stack` 清理分布式上下文。 |
| `collect_attn.py`；`op=attention_context/attention_generation`；`PerfFile.CONTEXT_ATTENTION/GENERATION_ATTENTION` | vLLM attention backend kernel，不含外部 QKV 投影。 | vLLM v1 attention selector/backend、paged KV cache metadata。 | BF16 attention；KV cache 支持 BF16/FP8。FP8 KV cache dtype 在 cache 创建和 backend selector 中配置，主测为 backend forward。 | attention 标准字段：`batch_size,isl,num_heads,num_key_value_heads,head_dim,beam_width,kv_cache_dtype,attn_dtype,step,latency`。 | 构造 VllmConfig、KV cache、metadata → 选择 backend → 调用 `impl.forward` → benchmark → 写 context/generation。 | `kernel_source` 记录具体 backend 名，如 `vllm_flash_attn` 风格；支持 vLLM 新旧 attention registry fallback。 |
| `collect_moe_v1.py`；`op=moe` route `<0.17`；`PerfFile.MOE` | vLLM fused MoE compute。 | vLLM `FusedMoE`、FlashInfer fused MoE、Marlin、MXFP4/NVFP4 helper。 | `bfloat16`、`fp8`、SM90+ `fp8_block`、`int4_wo`、SM100+ `mxfp4/nvfp4`；MXFP4 分支 `FusedMoE.forward` 内 routing，其他分支可能预先生成 topk 后执行 fused experts。 | MoE 标准字段；`kernel_source=vllm_fused_moe/vllm_marlin_moe/vllm_mxfp4_moe/vllm_flashinfer_trtllm_moe_fp4`。 | 枚举 common MoE → 构造 quant config/专家权重/router logits → benchmark `run_single_iteration` → 写 MoE 表。 | power-law 分布可多 logits 逐次执行；`allow_graph_fail=True`。 |
| `collect_moe_v2.py`；`op=moe` route `>=0.17`；`PerfFile.MOE` | 新版 vLLM MoE compute，接口与 quant 分支更新。 | vLLM forward context、FusedMoE layer、FlashInfer FP4 / DeepGEMM helper。 | `bfloat16`、`int4_wo`、`fp8`、`fp8_block`、MXFP4/NVFP4；动态 routing/forward 是否计入取决于分支，`run_single_iteration` 内调用的部分均计入。 | MoE 标准字段；int4 source 为 `vllm_marlin_int4_moe`。 | 构造 forward context 和 expert map → 生成 routing/topk → benchmark → 写表。 | v2 增加 forward context 和 tile tokens 兼容检查；OOM 时允许已完成 token 点落盘。 |
| `collect_mla_module_v1.py`；`op=mla_context_module/mla_generation_module/dsa_context_module/dsa_generation_module` route `<0.17`；模块 PerfFile | 完整 DeepSeek MLA/DSA attention module forward。 | vLLM `MLAAttention`、DeepSeekV2 model、modelopt/fp8 quant config。 | `gemm_type=bfloat16/fp8_block/nvfp4`，`kv_cache_dtype=bfloat16/fp8`；compute dtype 可 BF16/FP8，权重处理在 forward 前，主测 module forward。 | `model,architecture,mla_dtype,kv_cache_dtype,gemm_type,num_heads,batch_size,isl,tp_size,step,latency`。 | 构造 fake HF/VllmConfig → 初始化单层 attention module → process weights → 创建 KV cache/metadata → set forward context → benchmark forward → 写模块表。 | v1 适配旧 vLLM API；fake model config 固化 DeepSeek MLA/DSA 结构。 |
| `collect_mla_module_v2.py`；同 op route `>=0.17,<0.19`；模块 PerfFile | 完整 MLA/DSA module，vLLM 0.17 API。 | vLLM v1 forward context、`MLAAttentionSpec`、attention selector。 | BF16/FP8 KV；DSA FP8 使用 `fp8_ds_mla` 自定义 cache 格式；GEMM 支持 `bfloat16/fp8_block/nvfp4`。 | 同模块字段。 | 额外创建 DSA indexer KV cache 和 metadata → 绑定到 `static_forward_context` → benchmark forward。 | 区分 dense MLA FP8 与 DSA `fp8_ds_mla`；KV cache 预填历史 token，decode 更接近真实场景。 |
| `collect_mla_module_v3.py`；同 op route `>=0.19`；模块 PerfFile | 最新完整 MLA/DSA module。 | vLLM v1 `MLAAttention`、attention selector、forward context、workspace manager。 | 同 v2；SM90+ 才加入 FP8 KV，SM100+ 可加入 NVFP4 / FP8 compute 组合。 | 同模块字段。 | 构建 module/config/cache/metadata → 设置 current config 与 forward context → `kernel_func` 调 module → benchmark → 写表。 | DSA context 关闭 CUDA Graph，避免 flashmla-sparse workspace 被 graph 私有池长期持有；其余路径保留 graph。 |
| `collect_gdn.py`；`op=gdn`；`PerfFile.GDN` → `gdn_perf.txt` | GDN Conv1D 与 delta-rule scan/update 子 kernel。 | vLLM FLA ops、Mamba causal conv1d ops。 | BF16 路径。 | GDN 标准字段；`kernel_source` 区分 `causal_conv1d_fn/chunk_gated_delta_rule/causal_conv1d_update/fused_recurrent_gated_delta_rule`。 | context/generation 分别准备输入池 → benchmark 子 kernel → 写 GDN 表。 | 与 SGLang/TRT-LLM 同结构，便于后端横向对比；默认轮换 input pool。 |

## XPU 附表

| 所属文件与注册标识 | 测试粒度界定 | 核心执行载体 | 包含的量化类型与前置转化全景 | 输入变量与保存的数据表 | 代码执行过程要点解析 | 特殊设计 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `collect_gemm_xpu.py`；`REGISTRY_XPU op=gemm`；`PerfFile.GEMM` | XPU GEMM/Linear 单算子。 | vLLM XPU Linear/DeepGEMM 兼容路径。 | 与 CUDA GEMM 类似，但按 XPU backend 能力过滤。 | `gemm_dtype,m,n,k,latency`。 | 生成 XPU 用例 → 构造 op → benchmark → 写 GEMM 表。 | 使用 `get_device_module()` 抽象 CUDA/XPU device API。 |
| `collect_attn_xpu.py`；`REGISTRY_XPU op=attention_context/generation`；Attention PerfFile | XPU attention backend kernel。 | vLLM XPU attention backend selector。 | BF16/FP8 KV 取决于 XPU backend 支持。 | attention 标准字段。 | 构造 metadata/cache → backend forward → benchmark → 写 attention 表。 | 与 CUDA attention 文件平行维护。 |
| `collect_moe_xpu.py`；`REGISTRY_XPU op=moe`；`PerfFile.MOE` | XPU fused MoE compute。 | `vllm_xpu_kernels.fused_moe_interface`、vLLM FusedMoE layer。 | BF16 / MXFP4 等 XPU 支持类型；闭包内 forward/routing 计入。 | MoE 标准字段；`kernel_source=vllm_xpu_moe` 或 `vllm_xpu_moe_mxfp4`。 | 枚举 common MoE → 构造 logits/weights → benchmark → 写 MoE 表。 | 设备名通过 `get_device_module().get_device_name()` 获取。 |
