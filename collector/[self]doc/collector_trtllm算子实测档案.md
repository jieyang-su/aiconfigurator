# TensorRT-LLM collector 算子实测档案

## Registry 覆盖

TRT-LLM `REGISTRY` 覆盖 GEMM、ComputeScale、Attention、MLA、MLA BMM、MoE、WideEP MoE compute、Mamba2、GDN、MLA/DSA module。版本分叉集中在 `collect_mla_v1/v2.py` 与 `collect_moe_v1/v2/v3.py`。`collect_computescale.py` 除注册的 `computescale_perf.txt` 外，还额外写 `scale_matrix_perf.txt`，SDK 有对应 `PerfDataFilename.scale_matrix` loader。

| 所属文件与注册标识 | 测试粒度界定 | 核心执行载体 | 包含的量化类型与前置转化全景 | 输入变量与保存的数据表 | 代码执行过程要点解析 | 特殊设计 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `collect_gemm.py`；`op=gemm`；`PerfFile.GEMM` → `gemm_perf.txt` | 底层 Linear/GEMM 单算子。 | `tensorrt_llm._torch.modules.linear` 系列 Linear 与 TRT-LLM/DeepGEMM 后端。 | `bfloat16`、SM>86 `fp8/fp8_block`、SM100+ `nvfp4`；权重、scale、QuantConfig 在构造 Linear 时处理，主测为 `gemm.forward(x)`。 | `gemm_dtype,m,n,k,latency`。 | 准备 BF16 input → 构造多份 quantized Linear → dry run 初始化 → `kernel_func` 顺序 forward → benchmark → 写 `kernel_source=deepgemm` 或 `torch_flow`。 | `outside_loop_count` 多 op 摊薄误差；过滤 `nvfp4/fp8_block` 小 `n/k`。 |
| `collect_computescale.py`；`op=compute_scale`；`PerfFile.COMPUTESCALE` → `computescale_perf.txt`，另写 `scale_matrix_perf.txt` | FP8 动态量化前置开销拆分：compute scale 与 scale matrix。 | `torch.ops.tensorrt_llm.quantize_e4m3_per_tensor`、`static_quantize_e4m3_per_tensor`。 | 仅 FP8；动态量化闭包包含 scale 计算+矩阵量化，静态量化闭包只量化矩阵；`compute_scale_latency = dynamic - static`。 | `m,k,quant_dtype,latency`。 | 枚举去重 `(m,k)` → 分别 benchmark dynamic/static quant → 求差值并截断到非负 → 写 compute_scale 与 scale_matrix 两张表。 | 用差分法隔离 scale 查找开销；`outside_loop_count=5`。 |
| `collect_mla_v1.py`；`op=mla_context/mla_generation` via version route `<1.1.0`；`PerfFile.CONTEXT_MLA/GENERATION_MLA` | 细粒度 TRT-LLM MLA attention kernel。 | TRT-LLM `_torch.attention_backend` 与旧版 MLA metadata/resource manager。 | 仅 BF16 KV/cache；不支持 FP8。 | `mla_dtype=bfloat16,kv_cache_dtype=bfloat16,num_heads,batch_size,isl,tp_size,step,latency`。 | 构造 paged KV cache 与 attention metadata → context/generation 分支调用 TRT attention → benchmark → 写 MLA 表。 | 老版本兼容文件，未复用 `common_test_cases.py`。 |
| `collect_mla_v2.py`；`op=mla_context/mla_generation` via version route `>=1.1.0`；同上 PerfFile | 细粒度 TRT-LLM MLA attention kernel，新版 metadata/API。 | TRT-LLM binding executor、attention backend、`AttentionRuntimeFeatures`。 | BF16 attention compute；KV cache 支持 BF16/FP8。FP8 cache 在 cache 创建阶段指定，主测为 attention 调用。 | 同 MLA 标准字段，`kv_cache_dtype` 为 `bfloat16/fp8`。 | 生成 context/generation lengths → 构造 cache manager、metadata、latent cache → 调用 attention backend → benchmark → 写表。 | TRT-LLM 1.3+ 调整 `tokens_per_block` 到 32；decode 写 `step=max_context_sequence_length`。 |
| `collect_attn.py`；`op=attention_context/attention_generation`；`PerfFile.CONTEXT_ATTENTION/GENERATION_ATTENTION` | 标准 attention kernel，不含外部投影。 | TRT-LLM `_torch.attention_backend`、paged KV cache manager。 | BF16 attention；可测 FP8 KV cache / backend 支持的低比特 cache，主测不含 BF16→FP8 激活动态量化。 | attention 标准字段：`batch_size,isl,num_heads,num_key_value_heads,head_dim,beam_width,kv_cache_dtype,attn_dtype,step,latency`。 | 构造 mapping/model/resource/metadata → 准备 q/k/v/KV cache → 调 backend forward → benchmark → 写 context/generation。 | 与 SDK attention loader 的 `n_kv=0` MHA 约定保持一致。 |
| `collect_mla_bmm.py`；`op=mla_bmm_gen_pre/mla_bmm_gen_post`；`PerfFile.MLA_BMM` | MLA decode pre/post BMM 单算子。 | `torch.ops.trtllm.bmm_out`、`fp8_batched_quantize_1x128_permute102`、`fp8_block_scaling_bmm_out`。 | `bfloat16`、SM90+ `fp8`；FP8 分支在 `kernel_func` 内执行激活动态量化再 BMM，因此量化开销计入 latency。 | `bmm_dtype,num_tokens,num_heads,latency`；`op_name=mla_gen_pre/post`。 | 初始化 q/latent、投影权重与 scale → BF16 直接 bmm_out 或 FP8 量化+BMM → benchmark → 写共享 BMM 表。 | pre/post 对应 `kv_lora_rank/qk_nope/v_head_dim` 的两个固定矩阵形状。 |
| `collect_moe_v1.py`；`op=moe` route `>=0.20,<0.21`；`PerfFile.MOE` | TRT-LLM fused MoE compute，旧版接口。 | `tensorrt_llm._torch.modules.fused_moe.FusedMoE`。 | `bfloat16`、FP8 等早期支持；routing logits 传入 forward，FusedMoE 内部 routing/专家执行计入。 | MoE 标准字段；`kernel_source=moe_torch_flow` 或 min-latency。 | 枚举 common MoE → 构造 FusedMoE 和 router logits → `moe.forward(...)` → benchmark → 写 MoE 表。 | SM100 可选 min-latency 模式。 |
| `collect_moe_v2.py`；`op=moe` route `>=0.21,<1.1`；`PerfFile.MOE` | DeepSeek/Qwen 等新版 MoE compute。 | TRT-LLM autotuner、DeepSeek model config、FusedMoE。 | BF16/FP8/block FP8 等；权重量化/配置在构造期，forward 内含 routing 与 expert kernel。 | MoE 标准字段。 | 根据模型配置生成专家与 logits → 选择 backend → benchmark → 写表。 | 引入 autotuner 和模型结构差异处理。 |
| `collect_moe_v3.py`；`op=moe` route `>=1.1`；`PerfFile.MOE` | 最新 MoE compute，含 DeepGEMM/CUTLASS/non-gated/min-latency 分支。 | `DeepGemmFusedMoE`、CUTLASS MoE、TRT-LLM custom ops。 | `bfloat16`、`fp8_block`、`nvfp4`、部分非 gated MoE；power-law 时可多 logits，闭包内 forward 包含实际 routing/专家 compute。 | MoE 标准字段；`kernel_source=deepgemm/moe_torch_flow_cutlass/moe_torch_flow_nongated/...`。 | 解析模型 config → 创建 hidden/router → 选择 backend/source → benchmark → 写表 → 对 DeepGEMM buffer 做清理并退出 worker。 | 任务后 `sys.exit(EXIT_CODE_RESTART)` 强制释放 CUDA/DeepGEMM 缓存。 |
| `collect_wideep_moe_compute.py`；`op=trtllm_moe_wideep`；`PerfFile.WIDEEP_MOE` → `wideep_moe_perf.txt` | TensorRT-LLM WideEP expert compute 模拟，不含真实跨节点通信。 | TRT-LLM WideEP MoE op、CUTLASS/DeepGEMM MoE kernel。 | `bfloat16/fp8_block/nvfp4` 等随硬件和 kernel；动态 token 分布/slot 模拟在测量输入准备中完成，主测为 compute kernel。 | `moe_dtype,moe_kernel,num_tokens,dp_num_tokens,rank0_num_tokens,hidden_size,inter_size,topk,num_experts,num_slots,moe_tp_size,moe_ep_size,distribution,simulation_mode,latency`。 | 枚举 WideEP 模型/分布/kernel → 构造 rank0 本地 tokens 和 slots → benchmark compute → 写 `op_name=wideep_moe(_eplb)`。 | 支持 EPLB 后缀、accurate/simple simulation；数据库按 `kernel_source=wideep_compute_*` 查询。 |
| `collect_mamba2.py`；`op=mamba2`；`PerfFile.MAMBA2` → `mamba2_perf.txt` | Mamba2 拆分 kernel：Conv1D 与 SSM scan/update。 | TRT-LLM `causal_conv1d_fn/update`、`mamba_chunk_scan_combined`、`selective_state_update`。 | BF16 路径，无低比特量化。 | `phase,batch_size,seq_len,num_tokens,d_model,d_state,d_conv,nheads,head_dim,n_groups,chunk_size,model_name,latency`；`kernel_source` 区分子 kernel。 | context 测 causal conv 与 chunk scan；generation 测 conv update 与 selective state update → 写同一 Mamba2 表。 | 默认 input pool 轮换，支持 cached input；`allow_graph_fail=True`。 |
| `collect_gdn.py`；`op=gdn`；`PerfFile.GDN` → `gdn_perf.txt` | GDN Conv1D 与 delta-rule scan/update 子 kernel。 | TRT-LLM FLA chunk/recurrent modules 与 Mamba conv1d。 | BF16 路径。 | GDN 标准字段，`kernel_source=causal_conv1d_fn/chunk_gated_delta_rule/causal_conv1d_update/fused_recurrent_gated_delta_rule`。 | context/generation 两套 benchmark 函数分别测 conv 与 GDN kernel → 写 GDN 表。 | 与 SGLang 版本结构几乎一致，便于同表比较。 |
| `collect_mla_module.py`；`op=mla_context_module/mla_generation_module/dsa_context_module/dsa_generation_module`；`PerfFile.MLA_*_MODULE/DSA_*_MODULE` | 完整 DeepSeek MLA/DSA self-attn module forward。 | TRT-LLM `DeepseekV32Attention`、model loader、KV cache manager、attention backend。 | `gemm_type=bfloat16/fp8_block/nvfp4`；`kv_cache_dtype=bfloat16/fp8`；attention compute 当前记录 BF16。权重量化由 model config / loader 处理，主测为完整 module forward。 | `model,architecture,mla_dtype,kv_cache_dtype,gemm_type,num_heads,batch_size,isl,tp_size,step,latency`。 | 构建模型配置并应用 gemm quant → 加载/patch module → 创建 KV cache/metadata → `attention_module.forward` → benchmark → 写模块表。 | RC 版本中 patch `post_load_weights` 兼容 API；按 attn type 选择 MLA/DSA 文件。 |
