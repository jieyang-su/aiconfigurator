# SGLang collector 算子实测档案

## Registry 覆盖

SGLang `REGISTRY` 覆盖 GEMM、细粒度 MLA/MLA-BMM、Attention、MoE、WideEP MLA/MoE、DSA、DeepSeek-V4 Flash、GDN、MHC。`collect_wideep_deepep_moe.py` 的 registry 入口是 `wideep_moe` / `PerfFile.WIDEEP_MOE`，但运行时实际写入 `wideep_context_moe_perf.txt` 与 `wideep_generation_moe_perf.txt`，这与 `PerfDatabase` 的 SGLang WideEP MoE loader 对齐。

| 所属文件与注册标识 | 测试粒度界定 | 核心执行载体 | 包含的量化类型与前置转化全景 | 输入变量与保存的数据表 | 代码执行过程要点解析 | 特殊设计 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `collect_gemm.py`；`op=gemm`；`PerfFile.GEMM` → `gemm_perf.txt` | 底层单算子 GEMM / Linear。 | SGLang DeepGEMM wrapper、`fp8_scaled_mm` / FlashInfer、BF16 matmul 路径。 | `bfloat16`、`fp8`、`fp8_block`、`int8_wo`、`nvfp4`；权重和 scale 多在 op 构建阶段准备，主测闭包主要执行 GEMM forward。 | 用 `get_gemm_common_test_cases()` 的 `m/x,n,k`；保存 `gemm_dtype,m,n,k,latency`。 | 生成输入和量化权重 → 构造多份 GEMM op → `kernel_func` 逐个执行 → `benchmark_with_power` → 写 `op_name=gemm,kernel_source=sglang`。 | 设置 `SGLANG_JIT_DEEPGEMM_PRECOMPILE=0` 避免 DeepGEMM 为同 `N,K` 编译所有 M；多 op 列表摊薄 launch 并减少缓存偏差。 |
| `collect_mla.py`；`op=mla_context/mla_generation`；`PerfFile.CONTEXT_MLA/GENERATION_MLA` | 细粒度 MLA attention kernel，不含完整 layer QKV 投影。 | `RadixAttention` + `FlashAttentionBackend` / `TritonMLABackend` / `TRTLLMMLABackend`。 | `mla_dtype` 固定记录 `bfloat16`；KV cache 支持 `bfloat16` / `fp8`。FP8 KV 的 q/k/v 转 dtype 在 benchmark 前完成，不把动态量化计入主测。 | context/generation 的 `input_len,batch_size,num_heads,tp_size,tokens_per_block`；保存 `mla_dtype,kv_cache_dtype,num_heads,batch_size,isl,tp_size,step,latency`。 | 构造 mock model/server/cache/forward batch → 初始化 backend metadata → `layer(q,k,v,forward_batch, q_rope,k_rope)` → 写 context 或 generation 表。 | SM90+ 才生成 MLA 用例；SM120 generation 对 KV dtype 有特殊过滤；`step=0` 表示 context，`step=input_len` 表示 decode past KV。 |
| `collect_mla_bmm.py`；`op=mla_bmm_gen_pre/mla_bmm_gen_post`；`PerfFile.MLA_BMM` → `mla_bmm_perf.txt` | MLA decode 前后处理 BMM 单算子。 | BF16 `torch.bmm`；FP8 `sgl_kernel.bmm_fp8` + `per_tensor_quant_mla_fp8`。 | `bfloat16`、`fp8`；FP8 分支在 `kernel_func` 内对激活执行 per-tensor quant，再调用 FP8 BMM，因此量化前置开销计入 latency。 | `num_tokens,num_heads,dtype`；保存 `bmm_dtype,num_tokens,num_heads,latency`，`op_name` 区分 `mla_gen_pre/post`。 | 初始化 q/latent 和投影权重 → BF16 直接 BMM 或 FP8 闭包内量化+BMM → benchmark → 写共享 BMM 表。 | 用 `get_sm_version()` 控制 FP8；pre/post 共用一个 CSV，数据库靠 `op_name` 查询。 |
| `collect_attn.py`；`op=attention_context/attention_generation`；`PerfFile.CONTEXT_ATTENTION/GENERATION_ATTENTION` | 标准 MHA/GQA/MQA attention kernel，包含 SGLang attention layer forward，不含外部 QKV Linear。 | `RadixAttention` + SGLang FlashAttention / Triton / TRTLLM MHA backend。 | BF16 attention；SM90+ 可测 FP8 context FMHA 和 FP8 KV cache。q/k/v 若需 FP8 在 benchmark 前转换，主测主要是 attention forward。 | `b,s,num_heads,num_key_value_heads,head_dim,use_fp8_kv_cache,use_fp8_context_fmha,phase`；保存 attention 标准字段与 `latency`。 | 构造 req/token/KV pool → 初始化 `ForwardBatch` 和 backend metadata → 可选 q/k/v cast → `layer(q,k,v,forward_batch)` → 写 context/generation 表。 | `num_key_value_heads=0` 表示 `n_kv==n` 的 MHA 约定；context 可同时枚举 FP8 FMHA 与 FP8 KV。 |
| `collect_moe.py`；`op=moe`；`PerfFile.MOE` → `moe_perf.txt` | 复合 MoE compute：包含 routing/topk 或已生成 workload 下的 fused experts，视分支而定。 | `fused_moe_triton`、Marlin MoE、FlashInfer CuteDSL/NVFP4 MoE、SGLang topk。 | `bfloat16`、`fp8_block`、`int4_wo`、SM100+ `nvfp4`；若 `workloads is None`，闭包内会根据 gating 做 `select_experts`，routing 开销计入；EP>1 的 balanced/power_law 预生成本地 workload，主测更偏专家 GEMM。 | 来自 `get_common_moe_test_cases()`：`num_tokens,hidden_size,inter_size,topk,num_experts,tp,ep,distribution`；保存 MoE 标准字段。 | 选择 dtype/kernel → 生成 hidden/router/workload → 构造 `run_op(i)` → `outside_loop_count=5` → benchmark → 写 `kernel_source=sglang_fused_moe_triton/sglang_marlin_moe/sglang_flashinfer_cutedsl_moe`。 | 对 power-law 分布生成多组 logits；`allow_graph_fail=True` 防止 torch.compile 路径 graph capture hang；FP4 分支按 expert 预量化权重。 |
| `collect_mla_module.py`；`op=wideep_mla_context/wideep_mla_generation/dsa_context_module/dsa_generation_module`；`PerfFile.WIDEEP_CONTEXT_MLA/WIDEEP_GENERATION_MLA/DSA_*` | 完整 attention module 级别，包含模型 self-attn forward 相关 pre/post 与 backend attention，不只是 kernel。 | SGLang `ModelRunner`、DeepSeek MLA/DSA attention module、FlashInfer/FA3/FlashMLA backend。 | `bfloat16`、`fp8` KV，`gemm_type` 可为 `bfloat16/fp8_block/nvfp4`；权重量化和模块初始化在测量前，forward 内包含模块实际调度和内部投影/attention。 | `model,architecture,mla_dtype,kv_cache_dtype,gemm_type,num_heads,batch_size,isl,tp_size,step,latency`；WideEP MLA 写 `wideep_*_mla_perf.txt`，DSA 写 `dsa_*_module_perf.txt`。 | 加载 dummy model/runner → 准备 batch/KV cache/positions/hidden → context 手动 event 统计，generation 用 `benchmark_with_power` → 写模块级 CSV。 | WideEP MLA 复用旧 `op_name=mla_context/generation` 和 `kernel_source=backend_name`；DSA generation 使用 `isl=1,step=seq_len`。 |
| `collect_dsv4_flash_attn.py`；`op=dsv4_flash_csa_context_module/dsv4_flash_hca_context_module/dsv4_flash_csa_generation_module/dsv4_flash_hca_generation_module`；`PerfFile.DSV4_FLASH_*` | DeepSeek-V4-Flash CSA/HCA attention module 级压测。 | SGLang engine/model runner、compressed FlashMLA 路径。 | 组合来自 `common_test_cases`：`compute_dtype=bfloat16`、`kv_cache_dtype=fp8`、`gemm_type=bfloat16/fp8_block`；低比特投影配置由子进程启动参数设置，主测为模块 forward。 | 每个 kind+mode 一个 CSV：`model,architecture,mla_dtype,kv_cache_dtype,gemm_type,num_heads,batch_size,isl,tp_size,step,compress_ratio,latency`。 | registry 测试用例 → worker 子进程运行指定 kind/mode/tp/gemm → benchmark module → `_log_perf()` 写 split file。 | 一个 CSV 汇总同 kind+mode 的所有 TP/GEMM；`compress_ratio` 区分 CSA/HCA；`PerfDatabase` 会 merge split 文件到 DeepSeek-V4 attention module 数据。 |
| `deepseekv4_sparse_modules.py`；`op=dsv4_flash_paged_mqa_logits_module/dsv4_flash_hca_attn_module`；对应 `PerfFile.DSV4_FLASH_*_MODULE` | DeepSeek-V4-Flash 稀疏子 kernel 级补偿数据，不是完整 attention。 | DeepGEMM / sparse kernel helper，`paged_mqa_logits` 与 `hca_attn`。 | `paged_mqa_logits` 记录 `mla_dtype=fp8_e4m3`，`hca_attn` 记录 `bfloat16`；KV 固定 `fp8_e4m3`，`gemm_type=fp8_block`。 | `model,architecture,mla_dtype,kv_cache_dtype,gemm_type,num_heads,batch_size,isl,tp_size,step,compress_ratio,latency`。 | 枚举 `bs,isl,past_kv,tp_size` → 准备稀疏 kernel 输入 → `benchmark_with_power` → `_write_row()` 写默认 kernel CSV。 | 代码注释说明 `topk_512` 和 `csa_attn` 走解析建模，不采 CSV；这些文件用于 past-KV Δ 修正。 |
| `collect_wideep_deepep_moe.py`；`op=wideep_moe`；注册 `PerfFile.WIDEEP_MOE`，实际写 `wideep_context_moe_perf.txt` / `wideep_generation_moe_perf.txt` | WideEP + DeepEP + DeepGEMM MoE 模块/专家计算路径，含 token dispatch 后的本地 expert compute 模拟。 | SGLang DeepEP token dispatcher、DeepGEMM MoE layer。 | 固定 `moe_dtype=fp8_block`；hidden states 在准备阶段转 `float8_e4m3fn`，主测主要是 MoE GEMM/dispatch 后 compute，不测 BF16→FP8 动态量化。 | `moe_dtype,num_tokens,hidden_size,inter_size,topk,num_experts,moe_tp_size,moe_ep_size,distribution,latency`。 | 加载含 dummy weights 的模型层 → 生成 uniform/power-law routing → 模拟 EP token 分发 → 测 prefill/context 与 decode/generation → 写 split WideEP MoE 表。 | power-law alpha 覆盖 `0.6/0.8/1.01/1.02/1.2`；decode 使用 CUDA Graph；prefill 对 power-law 多采样取平均。 |
| `collect_gdn.py`；`op=gdn`；`PerfFile.GDN` → `gdn_perf.txt` | Gated DeltaNet 拆分子 kernel：Conv1D 与 GDN scan/update。 | SGLang FLA `chunk_gated_delta_rule`、`fused_recurrent_gated_delta_rule`、Mamba causal conv1d。 | BF16 数据路径，无低比特量化。 | `phase,batch_size,seq_len,num_tokens,d_model,d_conv,num_k_heads,head_k_dim,num_v_heads,head_v_dim,model_name,latency`；`kernel_source` 区分子 kernel。 | context 测 `causal_conv1d_fn` 与 chunk scan；generation 测 `causal_conv1d_update` 与 recurrent update → 写同一 GDN 表。 | 默认构造 input pool 轮换，环境变量可启用 cached input；同一 collector 产生多个 `kernel_source` 行供数据库分别查询。 |
| `collect_mhc_module.py`；`op=mhc_module`；`PerfFile.MHC_MODULE` → `mhc_module_perf.txt` | DeepSeek-V4 Hash-Compressed attention 的 MHC pre/post 模块 kernel。 | SGLang DeepSeek-V4 model runner / mHC pre/post module。 | 主要 BF16 激活路径；无通用 FP8 动态量化表述。 | `model,architecture,num_tokens,hc_mult,hidden_size,latency`，`op_name` 区分 pre/post。 | 枚举模型 hidden/hc_mult 与 token 数 → 构造 module 输入 → benchmark → `_log_result()` 写 MHC 表。 | 覆盖 V4-Flash/V4-Pro 及 FP8 namespace，但 pre/post kernel 配置来自缓存模型配置。 |
